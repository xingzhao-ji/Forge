0:00–2:00 — PROBLEM, STACK, ARCHITECTURE
Problem: dependent local tasks need durable state, observable attempts and predictable recovery rather than an opaque chain of function calls.
Stack: Python, SQLite, polling scheduler, four-worker thread pool, registered executor contracts and framework-neutral HTTP/SSE adapters.
Trace the path: submission → DAG validation/idempotency → persisted workflow/tasks/dependencies → claim runnable tasks → dispatcher/executor → outputs/events/artifacts → next eligible task.
Show README architecture, then runtime.py lines 21–36. Explain that this public extraction excludes private application routes and cloud-provider executors. It is a local single-process runtime.

7:00–12:00 — CODE DEEP DIVE
7:00 runtime.py lines 21–74: explicit data directory, component composition, executor registration and lifecycle. New runtime is required after stop.
8:00 store.py validate_submission (line 532), create_workflow (692): validate DAG before persistence; reject unsupported task types and cycles; deduplicate by idempotency key. Show actual tests for cycle rejection and repeated submission.
9:00 store.py claim_runnable_tasks (1341): transactionally claim only eligible work; check dependency success and concurrency limits; record attempt plan and lease.
10:00 dispatcher.py _run_task (45): load persisted input, execute registered task, save result; classify transient/cancelled/permanent errors; apply bounded retries and backoff.
11:00 scheduler.py _run_loop (49): recover expired leases, claim runnable tasks, dispatch, wait for the next poll. Discuss why polling is simple, and where it limits latency. Keep tests/test_runtime.py ready in a separate source tab.

12:00–15:00 — TRADEOFFS, BUGS, RETROSPECTIVE
12:00 SQLite plus a per-process thread pool makes this easy to reproduce, but it is not a distributed queue. Four workers is a per-process bound.
12:40 Default polling is 0.5 seconds and leases are 30 seconds. The dispatcher does not renew leases for long jobs, so do not promise exactly-once external side effects or safe arbitrary long-running work.
13:20 Cancellation does not forcibly interrupt running Python code; shutdown waits for workers. Custom executors need bounded execution.
14:00 Before exposing adapters publicly, add authentication and request/resource limits. Provider routing fixtures are synthetic metadata, not provider benchmarks.
14:30 Retrospective: explain what to improve next (lease renewal, idempotent side effects, resource limits and explicit observability) as proposed future work, not completed features.
14:50 Close on verified evidence: all 28 tests passed on this cloud environment. Do not attribute the private note-index refresh result (7.634 ms → 0.647 ms, about 91.5%) to Forge runtime throughput.
